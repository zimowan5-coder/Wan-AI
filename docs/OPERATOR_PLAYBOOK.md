# Wan-AI v0.2：给完全不懂代码的经营者的实操手册

> 重要：本软件只会自动处理已收到的真实询盘；没有客户、没有商户账户或缺少业务资质时，无法凭空产生利润。请遵守经营所在地的许可、税务与隐私法规。软件不是投资承诺。

## 第一阶段：先有第一个真实客户（建议 14 天验证周期）

默认只卖 **小型外贸团队的“询盘分类、回复草稿与跟进整理”服务**，先不做泛化“AI 自动创业”。
目标客户：已有独立站或 B2B 平台询盘邮箱、每周 5～50 条询盘、尚未使用成熟 CRM 的 1～10 人团队。
不适合：没有任何询盘的公司、需要自动替客户报价/承诺交期/直接代发商业报价的企业。

### 你要卖的东西（首轮定价只是测试假设，非市场公认价格）

- 体验包：199 元，一次性整理和处理 20 封真实询盘；回复草稿须由客户人工确认后发送。
- 标准包（测试提案）：499 元 / 月，最多处理 100 封，超量另议，不包括代发或代报价；只有真实需求验证后才上线自动续费。
- 不保证成交、不保证发信 SLA、不把模拟任务伪装为服务。
- 交付：分类清单、草稿、关键要素、优先级、按周汇总。实际询盘数据必须由客户授权，保留与删除责任另行约定。
- 成本：客户邮箱、可选模型 API、商户手续费、域名/服务器、人工审核时间。未计算这些成本前不声称“净利润”。

### 不懂技术也能做的五步

1. 运行 Windows 启动脚本，打开 http://127.0.0.1:8931；用自动生成的后台密码（如脚本已打印）登录。
2. 打开“首次配置”，确认专用业务邮箱的 IMAP（收件）和 SMTP（发件）是否填写。配置后先导入一封真实、已获授权的询盘验证。
3. 点“客户询盘”，检查意图/草稿，再从“审批中心”批准。**批准不代表已发送**。打开该询盘，确认收件人后再点“确认发送”。
4. 到客户自有店铺/独立站获取询盘，或由客户把邮件转发到授权邮箱；不要购买邮箱库、批量抓个人邮箱或未经同意群发。
5. 若已拥有合规商户账户，在 Stripe 后台创建一次性支付链接，填写 .env 的 WANAI_CHECKOUT_URL 和 STRIPE_WEBHOOK_SECRET，并将 webhook 指向 https://你的域名/api/billing/stripe；先用测试模式验证，之后切换真模式。**不支持自动续费和退款自动对账**。

### 收到付款时

- 只认经过 Stripe 官方签名验证的 checkout.session.completed 且 payment_status=paid 事件。
- 测试模式付款单独记“模拟”；真实 CNY 付款才计入真实 CNY 收入。其他币种放入待核对事件，不换算成人民币收入。
- 手工“标记成交”只是客户状态，不代表真实到账。未接入商户账单、退款和最终打款核销前不要拿控制台数值代替银行净收款。
- 必须履行服务、处理取消/退款请求，并定期核对 Stripe 商户后台的交易、手续费与实际到账。

## 每天只需要做什么（建议合计 15～30 分钟，视规模而定）

早上：打开“客户询盘”，查看待审批草稿，优先处理包含采购数量、明确询价的高分线索，核对事实并发送。
下午：查看付款记录、未完成交付和疑似 SMTP 失败。失败状态不是“没发”，请先在发件箱核实是否投递再人工决定。
每周：记录收到多少真实询盘、回复多少、多少成交、付费客户多少、退款和 API/邮件/人工成本多少。每次只改一处文案或流程，连续观察足够样本。
每月：至少导出/备份 data/wanai.db 和附件目录到加密离线盘，抽查客户数据留存。

## 安装说明与安全默认值

推荐 Python 3.11 或 3.12。双击 scripts/start_windows.bat；macOS/Linux 运行 bash scripts/start.sh。
第一次启动脚本会创建本地 .env，优先通过 bootstrap 脚本生成随机后台密码，密码只保存在本机 .env；**不要上传该文件**。
在 .env 配置 WANAI_IMAP_HOST/PORT/USER/PASSWORD 与 WANAI_SMTP_HOST/PORT/USER/PASSWORD/WANAI_FROM_EMAIL。
建议用邮箱服务商提供的“应用密码”，不推荐主账户密码；如果服务商只提供 OAuth，本版 IMAP/SMTP 不支持，不能冒称“已接通”。
默认 uvicorn 仅绑定 127.0.0.1。外网部署必须设置 WANAI_ADMIN_PASSWORD，使用 HTTPS 和反向代理，限制管理界面访问，并定期更新依赖。
公开展示的 /offer 页面不需要密码；正式部署前审查文案，确认有商业资质、退款条款、隐私告知、联系渠道。

## 常见故障

- 没收到邮件：看 IMAP 授权、应用密码、邮箱文件夹、UNSEEN 筛选；程序默认只读，不改变已读状态。
- 发送失败：先去邮箱“已发送”检查再判断是否重试，避免重复发送。
- 重启任务被标失败：防重复副作用的“隔离模式”；先检查第三方系统是否已执行，再手工决定重试。
- Stripe 收款没记账：检查 Webhook 真实/测试模式、验签密钥、货币是否 CNY，是否真实支付完成，以及 Stripe 的交付日志。
- 模型效果一般：默认 local 是规则模板，不是大语言模型。付费 API 调用还需 Key 和预算管理，绝不可用 Plus 订阅冒充 API 额度。
- 没客户：不是软件启动问题。先验证目标行业需求、拿到客户许可的数据与付费意向，别增加基础设施投入。

## 禁止行为 / 运营底线

不发送未经授权的广告邮件；商业营销邮件遵守目标地区反垃圾邮件、退订与隐私规则。
不承诺客户不确定的 MOQ、货期、价格和产品资质；对外合同、支出及发送均保留人审。
发现数据泄露或 API Key 暴露应立即撤销密钥、查看访问日志和通知相关方。

## 数据恢复
系统启动后及每隔约 24 小时，自动在 data/backups/ 生成包含 SQLite 数据库和 artifacts 文件的 ZIP 备份，默认保留最近 14 份。
**ZIP 未加密，仅为同一台设备上的快速恢复点，并非安全离站备份。**
定期把它复制到有密码的加密云存储或离线硬盘；谨防客户隐私泄露。
恢复前关闭服务，将 ZIP 内 wanai.db 复制回 data/，并恢复 artifacts/ 目录，启动后核对关键记录。

## 付费模型防误扣费
即使 .env 填入 OpenAI/Claude/Gemini Key，也默认不会付费调用；想启用需要手工设置 WANAI_ENABLE_PAID_AI=I_ACCEPT_PAID_API_COSTS。
本版金额是按代码内过时可能的单价计算的近似值，不是 API 商家账单，也不能保证严格硬上限。只有确认当前官方单价、供应商后台预算和实际账单后，才建议开启。
人工桥接流程：任务进入 awaiting_input 后，将提示词复制到自己的 AI 应用，粘贴回答回原任务，系统会把回答存为交付文档，不会重复调用未配置的模型。
