# Wan's AI Business OS 路线图

## v0.2（下一阶段）：让第一笔"真实"发生

按优先级排序，每项带验收标准：

1. **真实询盘来源接入（InquiryPilot 转正）**
   - 接入 1 个真实来源：邮箱（IMAP 读取询盘邮件）或独立站表单 webhook。
   - 验收：连续 2 周、人工确认草稿可用率 >80%，且有 ≥1 封真实跟进回复发出记录。
2. **模型 API 接入（可选，需批预算）**
   - 配置任一 API Key（建议从 Gemini Flash 开始，单价最低），`llm_probe` 走真实调用并记账。
   - 验收：控制台财务页出现第一笔 `api_cost` 真实记账；单次调用费用 <¥0.1。
3. **收款链路**
   - 按经营地区选支付（Stripe / 支付宝商家），`orders` 表增加真实订单，`is_simulated=0`。
   - 验收：第一笔真实收款进台账真实口径（金额不限，哪怕 ¥1）。
4. **定时任务**
   - Worker 增加 cron 表达式支持：每日市场情报扫描、每周经营复盘报告。
   - 验收：连续 7 天每天自动产出一份情报简报任务且成功。
5. **多用户/权限**：暂不做（单机单用户阶段不需要）。

## v0.3 及以后

- 新业务模块孵化流程：研究 → 小规模验证 → 模块化接入（参考 `app/modules/base.py` 注册机制）。
- 数据反馈闭环：经营数据 → 策略建议 → 低风险 A/B → 保留有效策略（提示词/参数版本化）。
- 部署形态：数据量/任务量上来后，把 Worker 拆成独立进程，SQLite 换 PostgreSQL（接口层已隔离，迁移成本低）。

## 不做的事（v0.1 阶段明确拒绝）

- Kubernetes、微服务拆分、复杂消息队列——单机阶段不需要。
- 为了"显得 AI"而堆 Agent 数量——能用确定性程序解决的，优先用程序。
- 未经验证的商业模式直接上自动获客/自动花钱——先有证据，再放权限。
