# 成长实验：先卖给第一批人，而不是用算法幻想订单

## 市场定位（根据现有源码选定）

唯一首发人群：有海外 B2B 询盘邮箱的中国小型外贸供应商（约 1～10 人团队）；痛点是老板漏看信、英文回复慢、无人分类/复盘。
核心价值：将“邮件堆”转为可审核回复与结构化跟进，降低漏单风险。**此价值主张尚未经过真实付费客户验证。**

## 核心实验：14 天、先测支付意愿

**第 1～3 天：** 先拿到 10 位潜在客户的自愿沟通机会（既有客户、朋友介绍、垂直外贸圈、公开产品反馈帖），问他们最近一周的真实询盘量、回复耗时和漏回次数。禁止编造采访记录。

**第 4～7 天：** 争取 3 家愿意授权提供少量脱敏邮件的试点，免费处理 5 条真实询盘，逐条人工审核。记录原始处理时间与审核后的时间，不用“AI感觉更好”当指标。

**第 8～14 天：** 向愿意继续的试点提出 199 元付费体验包，记录真实支付/拒绝原因。目标是至少 1 位真实付款客户；若全拒绝，先改定位或服务，不新增 Agent。

注意：这些数字是内部测试门槛，不是转化率预测，更不是盈利保证。

## 优先渠道排序

1. 已经取得联系/许可的外贸供应商、转介绍、行业群里的征集试用反馈帖（遵守群规则）。
2. B2B 平台或独立站运营者愿意授权接入的真实询盘邮箱。
3. 有实测案例后发布对比案例、教学文章和“漏单诊断”内容，吸引自愿咨询。
4. **不做** 抓取邮箱名单 → 冷启动大规模营销邮件 → 伪装真人 Agent 的链路。

## 每周经营指标（分母必须真实）

- 新增真实线索 = 新增、去重后的已授权询盘数量。
- 首次处理时延 = 收件到草稿完成；目前不提供准确 SLA。
- 审批通过率 = 审核通过草稿 / 完成审核草稿。
- 已发送率 = 成功发出的有效回复 / 获批草稿。
- 真实成交数 = 人工核对的付费客户数量；不等于询盘条数或“标记成交”按钮。
- 现金毛收入 = 已验证真实货币入账；退款、商户手续费、工资、服务器、API 成本另减。
- 续购 = 老客户下期再次付费的人数 / 到期客户数。当前版本尚无订阅结算系统。

### 停止条件

到第 14 天没有一位表示愿意付款的试点，暂缓付费 API/服务器升级；访谈问题是“是否真的每周有 5 条以上值得花钱整理的询盘？”
若审核发现模型编造价格、资质、交期，必须禁用自动发送并修复模板。
月度毛利为负、支付失败率异常、投诉增加时停止扩量。
