# InquiryPilot（外贸询盘 AI 处理与跟进）证据评估

> 任务书要求："优先评估 InquiryPilot……如果有证据表明其他模式更适合早期获客，可以提出调整。"
> 以下评估写进仓库，防画饼。

## 结论（v0.1）

**方向保留，模式降级**：InquiryPilot 作为首个业务模块保留，但 v0.1 只做
「来料加工」模式——用户粘贴询盘原文 → 意图分类 → 关键信息抽取 → 回复草稿 →
人工审批。不做自动获客、不做自动发送。

## 证据

1. **真实询盘来源 = 0**：Alibaba/独立站表单/询盘邮箱均未接入，没有账号授权，
   没有历史询盘数据。"自动发现商机→自动跟进"的链路在 v0.1 没有任何真实输入，
   做出来就是自嗨。
2. **可运行的部分已验证**（2026-10-16 实测）：
   - 英文询盘："2000 units bamboo toothbrushes for Germany" →
     意图=询价、数量=2000 units、国家=Germany → 英文回复草稿，人工一批即过。
   - 模拟批量：一次创建 N 条模拟询盘，逐条处理、逐条进审批，无一自动外发。
3. **风险**：自动发送=失控外发=品牌与法律风险。在没有"草稿可用率"数据之前，
   不开放任何自动发送。

## 转正条件（v0.2）

1. 接入 ≥1 个真实询盘来源（邮箱 IMAP 或表单 webhook）；
2. 连续 2 周人工确认草稿可用率 >80%；
3. 有 ≥1 封真实跟进回复的发出记录。
   满足后开放"半自动发送"（仍需逐封审批），再往后才考虑全自动。

## 为什么不换方向

- 用户已有外贸语境的兴趣表达，且"询盘处理"是明确的、高频的、可用规则+模板
  部分自动化的活，自动化比例天然高。
- 其他候选（AI 内容、数据订阅）在 v0.1 同样缺真实流量/付费数据源，换方向并
  不能更快拿到第一笔真实收入。先把"处理"做扎实，获客链路等 v0.2 用真实来源验证。
